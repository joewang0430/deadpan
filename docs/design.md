# 设计文档

最后更新：2026-10-29。这份文档记录已经定下的决定、还没定的问题，以及数据管线怎么用。

## 1. 研究问题

> 在小型本地模型上，把讽刺 persona 用 LoRA 学进权重，和用 system prompt 相比，能不能做到：该坚持时坚持，该让步时让步，无关的能力不受损？

| | 子问题 | 一句话 |
|---|---|---|
| RQ1 坚持 | 该保持风格的时候，风格稳不稳？ | 包括没训练过的话题、8 轮长对话 |
| RQ2 让步 | 该收起讽刺的时候，能不能收起？ | 敏感场景，包括对话中途才出现的敏感话题 |
| RQ3 不受损 | 和风格无关的能力有没有变差？ | 指令遵循、有用性、事实错误 |

评测方案见第 6 节。

对比三个系统：

| 系统 | 说明 |
|---|---|
| Base | 原版 Qwen3-4B-Instruct-2507 |
| Prompt-only | 同一个模型，加上 persona system prompt |
| LoRA | 用 persona 对话微调后的模型，不加 system prompt |

训练数据用 context distillation 的方式造：强的老师模型看着 persona prompt 回答真实用户问题，学生模型在训练时看不到这个 prompt。

## 2. 已定的决定

| 项目 | 决定 | 理由 |
|---|---|---|
| 方向 | persona 风格微调 | ECE496 已经覆盖 agent 部署，这个项目补语义层面的多样性 |
| 目标风格 | deadpan 式冷讽刺，直接，简洁，但必须真正有用 | 只选一种讽刺，评分标准才能写具体；参考 Sarc7 的分类 |
| 语言 | 训练和核心评测只用英文 | 读者、评测工具、评分可靠性都偏向英文 |
| 中文 | 可选扩展，只测不训 | 用 oasst2 里中文用户原生写的问题，测风格能否跨语言迁移，以及是否出现 language confusion |
| 学生模型 | Qwen3-4B-Instruct-2507 | 纯文本、无思考模式、Ollama 已验证、Apache 2.0、中英文都强 |
| 问题来源 | oasst2 的首轮用户问题 | Apache 2.0，人工编写，像真实聊天；英文约五千条，中文约六百条 |
| 老师模型 | DeepSeek V4 Pro 0813 | 两轮试点里风格最稳定、最简洁；V4.1 Flash 综合榜更高，但三分之一的回答不讽刺（见第 5 节） |
| API 平台 | OpenRouter | 一个 key 同时能调开源老师模型和更强的评分模型，接口兼容 OpenAI |
| 留出话题 | food_cooking 和 travel_places | 这两类完全不进训练集，用来测泛化；标注后两类共有 266 条可用问题，测试需要 180 条，够用 |
| 训练数据量 | 按原计划：2250 段对话（单轮 1800 + 多轮 450），暂不做数据量实验 | 第一次做微调，先把流程跑通；以后想做，可以直接从这 2250 段里抽子集训练，不用重新生成 |
| 敏感问题 | 用 LLM 补约 150 条：100 条混进 train_single（总数仍是 1800），50 条组成 test_sensitive | oasst2 里可用的敏感问题只有 38 条，学生学不会什么时候收起讽刺，也测不出来 |
| 训练数据里不放 system prompt | 是 | 这正是 context distillation；Ollama 的模板在没有 system prompt 时不会自动添加默认提示，训练和部署一致 |
| 训练几个 LoRA | 一个，用现有的 2110 段数据 | 目标是一个讲得通的研究，不是顶会论文。不为 RQ2、RQ3 补训练数据，而是如实报告训练数据示范过什么（见第 5 节的统计表），据此解读结果 |
| 评测范围 | 精简版，见第 6 节 | 只保留 persona 明确规定了正确做法的测试，每一项结果都有对错标准 |
| 微调阶段怎么分工 | 代码和配置我来写、来测；你负责开机器、上传文件、运行命令 | 你时间紧，必须在 10 月 29 日晚 8 点前开始训练 |

## 3. persona

完整定义在 [persona/system_prompt.md](../persona/system_prompt.md)。这一份文件同时用在三个地方：

1. Prompt-only 基线的 system prompt。
2. 老师模型造数据时的 system prompt。
3. 评分模型的评分依据，通过 [prompts/judge.md](../prompts/judge.md) 嵌入。

核心规则：先帮忙，再讽刺；讽刺对准处境，不对准用户；遇到悲伤、危机、紧急情况时完全收起讽刺。第一版是我写的，你读过以后可以随时改。改动后要重新跑数据生成，所以最好在正式生成之前定稿。

## 4. 数据管线

| 步骤 | 脚本 | 作用 | 用什么模型 |
|---|---|---|---|
| 01 | 01_collect_prompts.py | 从 oasst2 取首轮问题，过滤质量和长度，去重 | 不用模型 |
| 02 | 02_tag_prompts.py | 给每条问题标话题、是否敏感、是否适合短回答 | DeepSeek V4.1 Flash |
| 02b | 02b_sensitive_prompts.py | 按九类敏感场景（丧亲、紧急情况、自伤念头等）生成约 190 条用户问题，去掉近似重复的 | DeepSeek V4 Pro |
| 03 | 03_split.py | 划分训练池和五个测试集 | 不用模型 |
| 04 | 04_generate.py | 老师模型生成单轮和多轮对话，多轮里由模拟用户追问 | 老师：DeepSeek V4 Pro，待试点确认 |
| 05 | 05_judge.py | 评分模型给每一轮回答打分，不合格的整段丢弃 | GLM-5.3，待校准确认 |
| 05b | 05b_retry_rejected.py | 被淘汰的问题让同一个老师重新生成，最多再试两次，每次照样评分 | 同 04、05 |
| 06 | 06_build_sft.py | 生成最终训练文件，不含 system prompt | 不用模型 |

所有脚本都能断点续跑：中途断了，重新执行同一条命令即可，已完成的条目会自动跳过。

划分的数量在 [configs/pipeline.yaml](../configs/pipeline.yaml) 里：

| 集合 | 数量 | 用途 |
|---|---|---|
| train_single | 1800 | 单轮训练对话，其中 100 条是合成的敏感问题；过滤后会变少 |
| train_multi | 450 | 多轮训练对话，每段三到五轮 |
| test_seen | 150 | 训练话题里的新问题 |
| test_unseen | 150 | 留出话题的问题 |
| test_multiturn | 60 | 多轮漂移测试的起始问题 |
| test_zh | 120 | 中文扩展测试 |
| test_sensitive | 50 | 合成的敏感问题，九类均匀分布；测模型该收起讽刺时能不能收起 |

正式标注的结果（2026-10-29）：英文适合的问题 4064 条，其中敏感的只有 38 条；留出的两个话题共 266 条，够测试用的 180 条。

## 5. 试跑发现

### 老师模型试点（2026-10-29）

12 个训练问题，GLM-5.3 评分：

| 老师 | 平均词数 | 风格分 | 有用性 | 观察 |
|---|---|---|---|---|
| DeepSeek V4 Pro | 86 | 4.27 | 4.73 | 最贴近"简洁、冷面"的设定，也最便宜；漏了一个指令（鸡过马路题没写香蕉），被评分过滤掉了 |
| Kimi K3 | 175 | 3.10 | 4.60 | 常常完全丢掉 persona，变回普通的长篇 markdown 助手；输出价格贵 5 倍 |
| GLM-5.3 | 131 | 4.20 | 4.80 | 质量好，但偏长；DAW 那题编出了一个不存在的软件；而且它就是评分模型，自己给自己打分可能偏高 |
| Mistral Large 4 | - | - | - | 12 次请求全部返回 400 错误，可能是不支持关闭推理的参数，没继续排查 |

三个老师在敏感问题（猫肾衰竭）上都正确地收起了讽刺。

原始结果存档在 [results/pilot/round1/](../results/pilot/round1/)。

第一轮漏掉了 DeepSeek V4.1 Flash（2026 年 9 月发布）。按 Artificial Analysis 的综合智能指数，它超过了 V4 Pro 0813，每个 token 的价格便宜约 4 倍。不过这些榜单测的主要是推理、编程和 agent 任务，而且用的是最高推理档。我们关闭了推理，要比的是 persona 写作。另外，V4 Pro 在知识类测试（SimpleQA、GPQA、HLE）上仍然领先，这和事实错误率有关。所以第二轮试点只比较 V4 Pro、V4.1 Flash 和 GLM-5.3，问题增加到 20 个，并且使用加了 Identity 一节的新 persona。

### 第二轮试点（2026-10-29）

20 个训练问题，GLM-5.3 评分，原始结果在 [results/pilot/round2/](../results/pilot/round2/)。"按规则能保留"指按第 05 步的过滤规则，20 条里能留下几条。

| 老师 | 平均词数 | 风格分 | 风格低于 4 分（19 条非敏感） | 事实错误 | 按规则能保留 |
|---|---|---|---|---|---|
| DeepSeek V4 Pro | 103 | 4.37 | 0 | 1 | 19/20 |
| DeepSeek V4.1 Flash | 132 | 3.63 | 6 | 0 | 14/20 |
| GLM-5.3 | 167 | 4.33 | 0 | 0 | 20/20 |

- **V4.1 Flash 有用性很高，但语气不稳定。** 有三分之一的回答写成了普通的说明文，几乎不讽刺，比如身高、真空、静态类型这几题。它在综合智能榜上领先，在 persona 遵循上却落后，这一点本身就可以写进报告。另一个问题是，过滤会专门丢掉它"不讽刺"的那些回答，而这些多半是解释类问题，于是训练集会偏向容易开玩笑的话题。
- **V4 Pro 最稳定、最简洁。** 唯一的事实错误在 Qt 那题：它编了一个不存在的排序参数。评分模型抓到了，第 05 步会过滤掉。
- **GLM-5.3 偏长，而且出现了两处丢空格的错字**（"theanimated"、"thegrunt's"）。学生模型会把这种错字也学进去。它又是评分模型，有用性 20 题全是满分，自己给自己打分可能偏高。
- **Identity 修复生效了**：三个老师在"你和 ChatGPT 的区别"这题上都自称 Qwen3-4B。
- **评分模型的盲点**：Qt 那题，三个老师都说 `QDir::Name` 默认不区分大小写。按 Qt 文档，要加 `QDir::IgnoreCase` 才不区分，所以三个都说错了，但评分只给 V4 Pro 标了错误。评分模型对冷门技术细节的判断不可靠，人工校准时要专门抽查技术类回答。

**决定：老师用 DeepSeek V4 Pro（2026-10-29 确认）。** 和 Flash 相比，整个数据生成大约多花 3 到 4 美元，换来的是更稳定的风格。

### 小批量试跑（2026-10-29，单轮 50 段 + 多轮 50 段）

| | 保留 |
|---|---|
| 单轮 | 44/50（88%） |
| 多轮 | 33/49（67%），另有 1 段因为模拟用户返回空消息而失败，已加重试 |

淘汰原因：风格低于 4 分 18 次，有用性低于 4 分 8 次，事实错误 7 次。敏感问题 3/3 全部保留；没有出现自称其他模型的回答。

- **多轮保留率低是因为错误会累积，不是因为风格漂移。** 一段对话里只要有一轮不合格，整段就丢掉。按轮次看，平均风格分从第一轮的 3.96 到后面各轮的 4.2 左右，没有下降；不合格的大多出在第一、二轮，所以截断保留前半段也救不回来。
- **风格低分集中在长回答上**：200 词以上的回答有 15% 低于 4 分，200 词以下的只有 6%。典型情况是写脚本、写邮件，或者长篇技术解释，整篇只在结尾有一句冷笑话。训练集会因此稍微偏向短问答，但偏得不严重。
- **"先给结论"带来了自信的错误。** 有两条回答开头直接说 "No."，接着的解释却说明答案其实是 yes；还有一条把 128 KB 到 1.5 TB 的增幅算成了"约 120 万%"，实际约 12 亿%。这和冒烟测试里东方那个例子是同一类问题：persona 要求先给结论，模型就倾向于不加确认地下结论。评分模型都抓到了，第 05 步会过滤掉。评测时要专门比较三个系统的"自信错误"。
- **评分模型会误判。** 有一条说 "SimCity 比 Populous 早几个月"，被判成事实错误。实际上 SimCity 是 1989 年 2 月发布的，Populous 最早是 1989 年 3 月，老师基本说对了。加上第二轮 Qt 那题的漏判，评分模型既会漏判也会误判，人工校准必须做。

按这个保留率推算，正式运行大约能留下 1580 段单轮对话和 300 段多轮对话。这次试跑花了约 0.45 美元；按单轮和多轮的 token 用量分别推算，正式运行约 7 美元（老师约 5 美元，评分约 1.5 美元）。

**于是加了重试（第 05b 步）。** 被淘汰的问题让同一个老师重新生成，最多再试两次，每次照样评分，这就是 rejection sampling。和补新问题相比，重试有三个好处：问题集合不变，不用重新划分；试跑数据不浪费；被淘汰的多是长回答和技术题，重试能把它们救回来，减轻训练集偏向短问答的问题。

预计最后能留下约 2100 段，接近 2250，重试大约多花 2 美元。连试三次都失败的问题直接放弃，这类问题本身往往就有毛病，比如"给我推荐个电影"太含糊，老师只能先反问。

不换老师模型重试，有两个原因。一是换模型会让训练集里混进两种语气。二是其他候选都更差：Flash 常常不讽刺，GLM 本身就是评分模型，Kimi 会丢掉 persona。

### 正式数据（2026-10-29 完成）

| | 问题数 | 第一次就通过 | 重试后通过 | 最终保留 |
|---|---|---|---|---|
| 单轮 | 1797（另有 3 条老师一直返回空回答） | 1476（82%） | 235 | 1711（95%） |
| 多轮 | 450 | 311（69%） | 96 | 407（90%） |

第一次生成时的淘汰原因：风格低分 374，有用性低分 102，事实错误 100，敏感场景语气不当 23，表面规则 20（感叹号、套话等），侮辱用户 2。118 个敏感问题全部保留。

06 又去掉了 8 段被截断的对话。它们达到了 900 token 的上限，在句子中间断掉，而评分模型没把截断当成问题。现在生成时会直接检查 API 返回的截断标记，以后不会再有这种数据。

**最终 2110 段：训练集 2004 段，验证集 106 段**，其中 326 段来自重试，共 3320 个老师回答。回答长度中位数 108 词，最长约 700 词；整段对话最长约 2400 词，约 3400 token，训练时序列长度设 4096 就够了。话题分布偏向技术类（32%），和 oasst2 本身的分布一致。统计文件存档在 [results/data/](../results/data/)。

数据部分实际花费：包括标注、两轮试点、试跑在内一共 6.5 美元。

**训练数据里各种"该让步"的示范有多少**（解读评测结果时要用）：

| 该让步的情况 | 示范数量（共 2110 段） | persona 是否规定了正确做法 |
|---|---|---|
| 单轮敏感问题 | 117 | 是：完全收起讽刺 |
| 多轮对话中途转为敏感话题 | 1 | 是：同一条规则 |
| 用户提出明确的长度或格式要求 | 14 | 没有明确规定（只说"通常两到六句话"） |
| 用户要求别再讽刺 | 0 | 没有规定（反而要求整段对话保持同一种语气） |
| 承认不知道 | 9 个回答（共 3320 个） | 没有规定 |

LoRA 在使用时看不到 persona 原文，只能从示范里学规则。所以评测结果要按"训练时示范过"和"没示范过"分开解读，结论只针对"只用 persona 对话训练"这种做法。

代价是重试次数越多，越偏向"评分模型喜欢的回答"：评分模型漏判的错误，每多试一次就多一次混进来的机会。所以重试上限设为两次。另外，评测时如果还用同一个评分模型，LoRA 的分数可能偏高，见第 6 节的评分方式。

另外发现了**身份问题**：被问到"你和 ChatGPT 有什么区别"时，DeepSeek 说自己是 Anthropic 的 Claude，GLM 说自己是 Z.ai 的 GLM，评分模型都没发现。训练集里大约有 27 条这类问题（很多是 oasst 用户叫它 "Open Assistant"）。直接拿来训练，学生就会学到别人的身份。处理方式有两条：

- persona 加了一节 Identity：自称"运行在 Qwen3-4B 上的 AI 助手"。这对三个系统都成立。
- 代码规则检查新增 `other_identity`：回答里自称是其他模型的，在第 05 步直接淘汰。用试点的 36 个回答验证过，抓到了上面两条，没有误报。

### 冒烟测试

用本地 4B 模型同时当老师和评分模型跑通了全流程。有一个样本很说明问题：用户问东方 11 的最终 boss 怎么打，4B 模型斩钉截铁地说"这个游戏没有 boss"，这是错的。4B 评分模型也没发现，给了满分。

由此得到三点：

- **老师和评分模型都必须用强模型。** 小模型的事实错误和宽松打分会直接污染训练数据。
- **直接的 persona 可能放大自信的错误。** "先给结论"的规则会让模型在不确定时也说得很肯定。评测时要对比三个系统的事实错误率，这正是"对齐税"的一部分。
- **评分模型需要人工校准。** 你需要亲手标几十条，算出和评分模型的一致率。

## 5b. 相关工作（2026-10-29 查新，不算穷尽）

| 方向 | 已有工作 | 和我们的关系 |
|---|---|---|
| 微调和 prompt 比较 persona 持久性 | [Persona Cartography](https://arxiv.org/html/2607.07916v1)（五大人格、Llama-8B）；[公民讨论模拟](https://arxiv.org/pdf/2511.17813)；[EduPersona](https://arxiv.org/pdf/2510.04648)；[多轮 RL](https://arxiv.org/pdf/2511.00222) | 结论多是微调更稳。"LoRA 比 prompt 稳"只能算验证已知结论 |

| 爱好者模型 | HuggingFace 上的 [Sarcastic Reddit AI](https://huggingface-proxy.pages.dev/jimmeylove/week6Mli)（Llama-3.2-1B LoRA） | 没有评测 |
| 微调行为能否被 system prompt 压住 | [Persona Hierarchy](https://arxiv.org/html/2610.09384v1)（Qwen3-4B，单轮） | 明确把多轮对话列为未解决的问题 |
| persona 带来事实错误 | [Persona-Consistent Hallucination](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=6035874)（SSRN，未经同行评审） | 没比较 prompt 和 LoRA |

结论：没找到在"讽刺 persona + 小模型 + LoRA 对比 system prompt + 多轮"这个组合上做过严谨对比的研究。不过只靠"换一个风格再验证一遍 LoRA 更稳"，新意有限。讽刺和一般人格特质的不同之处在于：它在敏感场景里必须关掉，而且"直率"可能导致自信的错误。这两点才是值得主打的地方。正式写报告前，还要再做一次更系统的查新。

## 6. 评测方案（2026-10-29 定）

### 测什么

三个系统用完全相同的测试题。

| | 测试 | 数据 | 主要指标 |
|---|---|---|---|
| RQ1 坚持 | 训练过的话题 | test_seen，150 条 | 风格分 |
| | 没训练过的话题 | test_unseen，150 条（food、travel） | 风格分，和上一行比较看能否迁移 |
| | 8 轮长对话 | test_multiturn，60 段。训练数据只有 3 到 5 轮 | 每一轮的风格分，画出随轮次变化的曲线 |
| RQ2 让步 | 单轮敏感问题 | test_sensitive，50 条。训练里示范过 | 语气是否合适（不能有讽刺）、有用性 |
| | 对话中途转为敏感话题 | 新建约 50 段：先正常问答两轮，第三轮用户说出难过的事。用户的话事先写好，只用来测试，不用来训练。训练里几乎没有这种形式 | 转折那一轮的语气是否合适 |
| RQ3 不受损 | 指令遵循 | IFEval，541 条，程序自动判对错 | 准确率，按是否和 persona 冲突分成两个子集 |
| | 有用性和事实错误 | 上面 RQ1 的题目 | 评分模型的有用性分、事实错误率 |

可选，时间够再做，按优先级排列：

1. SimpleQA 抽 300 题，统计答对、答错、承认不知道的比例。
2. 中文 test_zh 120 条：测风格能否跨语言迁移，以及是否用英文回答中文问题。
3. 用 Sarc7 的分类统计讽刺手法。

去掉的测试及原因：

- "用户要求别再讽刺"：persona 没规定该怎么做，甚至要求整段对话保持同一种语气，所以没有标准答案。
- "system prompt 冲突"：对 Prompt-only 不适用，因为它的 system prompt 就是 persona 本身。

### 必须在看到结果之前定好的（2026-11-08 写评测脚本时定下，之后不再改）

**IFEval 冲突子集。** 判断依据是 persona 自己的默认设定："通常两到六句话""默认用纯文字段落"。指令要求的长度或结构超出这个默认，就算冲突。代码在 [src/persona_lora/ifeval/__init__.py](../src/persona_lora/ifeval/__init__.py)。834 条指令里有 176 条属于冲突子集。

| 指令类型 | 算冲突的条件 |
|---|---|
| 字数 `number_words` | 要求"至少"100 词或更多（六句话大约 100 词） |
| 句数 `number_sentences` | 要求"至少"7 句或更多 |
| 段落数 `number_paragraphs`、`nth_paragraph_first_word` | 要求 3 段或更多 |
| 列表、分节、加粗标记 `number_bullet_lists`、`multiple_sections`、`number_highlighted_sections` | 全部算冲突 |
| 其余 19 种（大小写、关键词、JSON、结尾短语等） | 不算冲突 |

**各项指标的计算方式。** 代码在 [src/persona_lora/evaluation.py](../src/persona_lora/evaluation.py) 的 `item_scores`。每道题先得到下面几个数，系统的得分是这些数在所有题上的平均值，置信区间对题目做 bootstrap。

| 测试集 | 指标 |
|---|---|
| seen、unseen | `style`：风格分 1-5，敏感题不计；`helpfulness`：有用性 1-5；`factual_error`：有事实错误的比例 |
| sensitive | `tone_ok`：语气合适（没有讽刺）的比例；`helpfulness` |
| pivot | `tone_ok_at_pivot`：第 3 轮语气合适的比例，**RQ2 的主要指标**；`style_before`：前两轮平均风格分，用来确认转折前系统确实在讽刺；`helpfulness_at_pivot` |
| multiturn | `style_turn1` 到 `style_turn8`：每一轮的平均风格分，画漂移曲线；`style`：8 轮的平均值。敏感的起始题两项都不计（60 段里有 1 段。2026-11-09 补：原代码只在 `style` 里排除了它，每轮曲线里没排除，在看结果之前改成一致） |
| IFEval | 四个标准数字（题目级和指令级，严格和宽松），加上冲突子集和非冲突子集上的指令级严格准确率 |

**生成和评分的设置。**

- 三个系统都由同一个 vLLM 0.32.0 服务器提供，精度 bf16。Base 和 Prompt-only 用原版模型，LoRA 是在原版模型上运行时加载 adapter，不用合并后的权重。
- 采样参数统一为 temperature 0.7、top_p 0.8、top_k 20，这是 Qwen 官方推荐值。最多生成 3072 个 token，被截断的回答会单独记录。（原定 1536。2026-11-09 小规模试跑，每个测试集 2 题，只看了截断数，没看任何评分：Base 在 8 轮对话后几轮每轮写到 850 到 970 词，16 轮里 5 轮被截断，会冤枉地压低它的有用性。所以三个系统统一提到 3072，试跑结果全部删掉重新生成。）训练后的样例已经显示，贪心解码会掩盖风格。
- 多轮漂移测试共 8 轮，模拟用户和生成训练数据时相同（DeepSeek V4.1 Flash）。
- 中途转折测试集：9 个敏感类别各 6 段，用户的三句话由 DeepSeek V4 Pro 事先写好并固定，三个系统看到的完全相同。
- 评分模型看到的对话里没有 system prompt，所以不知道回答来自哪个系统。

### 评分方式

- 评分模型用 GLM-5.3，评分标准和过滤数据时相同。
- 另加一个不同家族的评分模型 Claude Haiku 5.5（Anthropic），用同一份评分标准给所有回答打分。原因是训练数据是用 GLM 筛选的，只用 GLM 打分会对 LoRA 有利。
- 你亲手盲标约 100 个回答：三个系统的回答混在一起，看不到是哪个系统写的。用它算两个评分模型和人工的一致率。我会做一个简单的标注页面。
- 三个系统做配对比较，报告 95% 置信区间（bootstrap）。
- 三个系统在同一个推理环境、同一个精度下评测。开发调试时可以先用本地 Ollama，正式数字必须在同一套环境里跑。

### 结果怎么解读

- **RQ2**：按第 5 节的统计表，分"训练时示范过"和"没示范过"两种情况解读。结论只针对"只用 persona 对话训练"这种做法。"加入专门的让步示范"写进未来工作。
- **RQ3**：以 Base 为基准。
  - 只在冲突子集上变差，说明风格压过了用户指令。
  - 在无冲突子集上也变差，说明能力确实受损，训练配置太激进。
